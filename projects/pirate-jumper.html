SOLO DEVELOPMENT PROJECT

Pirate Jumper

An endless runner developed in Unity during my semester break, featuring a continuously generated modular world, reusable gameplay objects and persistent cosmetic progression.

OVERVIEW

Building an endless runner

Pirate Jumper was built around a simple core loop: survive for as long as possible, collect coins and use the earned currency to unlock cosmetic characters.

The project gave me the opportunity to experiment with reusable level segments, object pooling, persistent progression and systems that can continue running for an undefined amount of time.

01

ENDLESS WORLD SYSTEM

Moving the world instead of the player

Rather than continuously moving the player through the world, the player stays close to the origin while the environment moves past them.

I chose this approach because an endless game can otherwise reach increasingly large world coordinates. Keeping the active gameplay area near the origin avoids relying on continuously growing position values.

The world itself is assembled from reusable level segments. New segments are added ahead of the player while old sections are removed and reused once they are no longer required.

Why this approach?

The goal was to keep the playable area small, allow the run to continue indefinitely and avoid constantly keeping old level geometry active.

Segment generation

During gameplay the system checks the distance to the end of the current level and requests another segment when required.

GAMEPLAY ITEMS

Temporary gameplay modifiers

Collectable items modify the current run instead of permanently changing the character.

Some items manipulate the speed of the world while others temporarily interrupt or modify the normal movement behaviour.

Because world movement is handled centrally, these effects can modify one shared gameplay system instead of changing every level segment individually.

Why modify world speed?

Since the environment represents forward movement in the game, changing its speed provides a simple way to create effects such as boosts and slowdowns without changing the player's world position.

03

CHARACTER PROGRESSION

Unlockable cosmetic characters

Coins earned during gameplay can be spent on chests containing cosmetic characters.

Characters are divided into multiple rarity tiers: Common, Rare, Epic and Legendary. Each rarity has its own probability when opening a chest.

All characters use the same gameplay behaviour. The system was intentionally cosmetic so the player's progression provides additional goals without changing the balance of the endless-run gameplay.

Handling duplicates

If the player receives a character they already own, the duplicate is converted back into currency. Higher rarity duplicates provide a larger reward.

Rarity selection

A random roll determines which rarity pool is used when selecting a character. 

int randomNr = Random.Range(0, 100);

if (randomNr < 50)
{
    // Common
}
else if (randomNr < 85)
{
    // Rare
}
else if (randomNr < 95)
{
    // Epic
}
else
{
    // Legendary
}

04

PERSISTENT PROGRESSION

Keeping progression between runs

Pirate Jumper stores progression locally so that unlocks and player progress remain available between sessions.

Saved information includes unlocked characters, the currently selected character, chest progression, currency and local highscore data.

Why persistence matters

The individual runs are temporary, but the progression system gives players a longer-term objective and connects repeated runs to each other.

PROJECT TAKEAWAYS

What I learned

Pirate Jumper was one of my first projects where I focused more deliberately on reusable gameplay systems rather than simply making individual features work.

In particular, the project introduced me to object pooling, modular runtime level generation and persistent progression. It was also my first project where I consistently used Git for version control throughout development.
