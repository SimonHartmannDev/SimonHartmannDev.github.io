SOLO DEVELOPMENT PROJECT

Tanks of Chaos

A wave-based tank combat game developed as a solo project in Unity. Players fight increasingly large enemy waves, unlock new vehicles and improve their combat capabilities over the course of the game.

OVERVIEW

Building a complete combat loop

Tanks of Chaos was my first larger solo game project that I developed from an initial idea into a complete playable release.

The core loop revolves around surviving enemy waves, earning currency, unlocking vehicles and improving their combat capabilities.

The project includes multiple vehicles, enemy behaviours, weapon types, maps, upgrades and Steam integration.

WAVE SYSTEM

Increasing pressure over time

Combat is structured around consecutive enemy waves. The WaveManager controls when a wave begins, how many enemies need to be spawned and when the next wave can start.

Each wave increases the number of enemies the player has to fight. The system also supports separate boss enemies that can appear as part of the wave progression.

Enemy deaths are reported back to the manager so it can track how many enemies remain and automatically continue the game once a wave has been cleared.

Why use explicit wave states?

Separating the wave into start, active and end states gave me one place to control spawning, transitions and wave progression instead of distributing that logic across individual enemies.

Wave Management Enemy Spawning Game States Boss Waves

Wave state flow

The manager uses a small state system to handle transitions between preparing, running and ending a wave. 

public enum WaveStatus
{
    None,
    StartWave,
    WhileWave,
    EndWave
}

private void CurrentWaveStateChanged()
{
    switch (waveStatus)
    {
        case WaveStatus.StartWave:

            enemysAlive = 0;
            waveCount++;

            WaveCountUpdate?.Invoke(
                waveCount
            );

            StartCoroutine(
                WaitForWaveToSpawn()
            );

            break;


        case WaveStatus.EndWave:

            currentEnemysSpawned = 0;
            canSpawnEnemys = false;

            UpdateStatus(
                WaveStatus.StartWave
            );

            break;
    }
}

Scaling the wave size

The amount of enemies grows together with the current wave count, while designated boss waves use their own spawn behaviour. 

private int CalculateNewWave()
{
    if (waveCount % bosModulo == 0)
    {
        return 1;
    }

    return startEnemyWaveCount
        + waveCount;

ENEMY BEHAVIOUR

Multiple enemy movement patterns

Enemies use different movement modes to create variation between encounters. Some enemies continuously move toward the player, while others can prepare and perform a direct dash attack.

Another movement type uses slower turning and forward movement, producing a heavier enemy behaviour compared with the standard chasing enemies.

The system keeps the individual behaviours behind a shared movement component, allowing enemy prefabs to use different movement styles through configuration.

Why multiple movement modes?

I wanted enemy variety without requiring a completely separate movement script for every enemy type. Switching behaviour through one movement component allowed several enemy styles to share the same base system.

Enemy AI Chase Behaviour Dash Attacks Target Tracking

Configurable movement behaviour

Each enemy can select a movement type that determines how it reacts to the player's position. 

public enum MovementType
{
    still,
    movingTowardsEnemy,
    attackDash,
    MacMovement
}

private void HandleMovement()
{
    switch (movementType)
    {
        case MovementType.still:
            break;

        case MovementType.movingTowardsEnemy:
            moveTowardsEnemy();
            break;

        case MovementType.attackDash:
            HandleDash();
            break;

        case MovementType.MacMovement:
            SlowMovement();
            break;
    }
}

Off-screen enemy indicators

Enemies outside the camera view receive a screen-space indicator. The UI position is clamped to the edge of the screen so the player can still locate remaining enemies. 

Vector3 screenPosition =
    Camera.main.WorldToScreenPoint(
        target.position
    );

bool isOffScreen =
    screenPosition.x <= 0f ||
    screenPosition.x >= Screen.width ||
    screenPosition.y <= 0f ||
    screenPosition.y >= Screen.height;

if (isOffScreen)
{
    screenPosition.x = Mathf.Clamp(
        screenPosition.x,
        borderSize,
        Screen.width - borderSize
    );

    screenPosition.y = Mathf.Clamp(
        screenPosition.y,
        borderSize,
        Screen.height - borderSize
    );

    transform.position =
        screenPosition;
}

03

VEHICLE COMBAT

Separate tank movement and turret aiming

Vehicle movement and weapon aiming are handled independently. The tank body accelerates and turns according to player movement input while the turret rotates separately toward the mouse position.

Acceleration, deceleration and maximum speed are configurable values and can change depending on the current vehicle upgrades.

Weapon behaviour also varies between vehicles. Standard projectiles travel directly forward while other weapons can use targeted projectile behaviour.

Why separate turret and vehicle movement?

Allowing the tank body and turret to rotate independently gives the player the ability to keep aiming at enemies while moving in another direction, which became a central part of the combat controls.

Player Controller Unity Input System Turret Aiming Vehicle Upgrades Projectiles

Independent turret aiming

The mouse position is converted into world space and used to rotate the turret independently from the tank body. 

private void UpdateTurretTowards()
{
    Vector2 mousePosition =
        GetMousePostion();

    Vector3 direction =
        (Vector3)mousePosition
        - turretParent.position;

    float desiredAngle =
        Mathf.Atan2(
            direction.y,
            direction.x
        ) * Mathf.Rad2Deg;

    float rotationStep =
        turretRotationSpeed[
            turretRotationSpeedCount
        ] * Time.deltaTime;

    turretParent.rotation =
        Quaternion.RotateTowards(
            turretParent.rotation,
            Quaternion.Euler(
                0,
                0,
                desiredAngle
            ),
            rotationStep
        );
}

04

VEHICLE PROGRESSION

Unlocking different vehicles

Currency earned during combat can be used to unlock additional vehicles and maps.

The available vehicles include multiple tank and vehicle types, each represented by its own prefab and configuration.

The shop system keeps the unlock logic separate from the individual vehicle behaviour. A vehicle reports its type to the shop, which then updates the corresponding unlock state.

Why use multiple vehicles?

Unlockable vehicles gave the combat loop a longer progression goal while also allowing me to experiment with different movement and weapon behaviours inside the same game.

Vehicle Unlocks Shop System Multiple Vehicles Maps Steam Achievements

Vehicle unlock routing

Each vehicle has an identifier that the shop uses to update its corresponding unlock state. 

public void VehicleBought(
    VehicleNames name)
{
    switch (name)
    {
        case VehicleNames.T_4:
            UnlockT4();
            break;

        case VehicleNames.T_6:
            UnlockT6();
            break;

        case VehicleNames.T_D1:
            UnlockTD1();
            break;

        case VehicleNames.MG_Car:
            UnlockMGCar();
            break;

        case VehicleNames.SC_1:
            UnlockSpaceCraft();
            break;

        case VehicleNames.ReconVehicle:
            UnlockReconVehicle();
            break;
    }
}

PROJECT TAKEAWAYS

What I learned

Tanks of Chaos was an important step from small prototypes toward completing and releasing a larger solo game.

I implemented the full gameplay loop myself, including player controls, enemy behaviour, wave progression, multiple vehicles, upgrades, maps and the surrounding game systems required for a complete release.

Looking back at the project also made me much more aware of the importance of modular code structure and reusable systems. Those lessons influenced how I approached my later projects.
